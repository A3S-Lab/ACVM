### 身份、角色与能力

链上地址能验证签名，却不天然说明签名者是受许可的医疗模型、采购审批员或本任务 Validator。ACVM 概念模型因此把稳定身份、角色资格和本次最小权限拆开：DID 标识主体，VC 声明资质，UCAN/ZCAP 一类能力凭证限制资源、动作、期限与委托深度。

```ts file="authorize-capability.ts"
function authorize(request: ToolRequest, capability: Capability, task: Task) {
  assert(capability.subject === request.agentDid)
  assert(capability.resource === request.resource)
  assert(capability.actions.includes(request.action))
  assert(capability.expiresAt >= task.deadline)
  assert(capability.parentScope.contains(capability.scope))
  assert(!revocations.has(capability.id))
}
```

子 Agent 获得的能力必须只能收窄，不能扩大；凭证还需要短有效期、任务绑定与撤销检查，避免泄漏后成为永久权限。

### 链下数据承诺

业务数据库、HTTPS API 和对象存储中的明文通常不应复制到链上。执行者可以对规范化输入与输出做承诺，并附带来源证明、时间窗口和随机挑战。链上只保存固定大小的根与验证结果。

```text file="external-data-claim.txt"
claim = {
  source: "api.example.com",
  path: "/orders/42/status",
  disclosedValue: "delivered",
  observedAt: 1760000000,
  requestNonce: "0x...",
  responseCommitment: H(canonicalResponse || salt)
}
```

zkTLS/TLSNotary 一类技术可以证明“该 HTTPS 端点返回过指定字段”，却不能证明端点记录与现实一致。来源治理、数据新鲜度和撤销仍是协议的一部分。

### 远程证明的验证范围

TEE 可以生成 quote，把代码度量、模型哈希、平台安全版本、输入输出承诺和本次 nonce 绑定到硬件证明密钥。验证方检查厂商证书链、固件撤销状态与白名单后，确认预期工作负载在隔离环境中运行过。

```ts file="attestation-policy.ts"
function verifyAttestation(quote: Quote, task: Task) {
  assert(verifyVendorCertificateChain(quote))
  assert(ALLOWED_TCB_LEVELS.has(quote.tcbLevel))
  assert(quote.measurement === task.expectedImageMeasurement)
  assert(quote.inputRoot === task.inputRoot)
  assert(quote.nonce === task.attestationNonce)
  assert(!isRevoked(quote.platformId))
}
```

TEE 不会判断模型答案是否正确，也无法消除硬件供应链和侧信道风险。高价值任务可叠加独立 Validator、多厂商冗余或零知识证明。

### 增量证明

长任务可将第 `i` 步状态承诺记为 `zᵢ`，并证明关系 `R(zᵢ, inputᵢ, receiptᵢ, zᵢ₊₁) = 1`。IVC 或 folding 让新一步把旧证明状态一起累积，最终链上只验证固定大小的终结证明。

```text file="incremental-proof.txt"
z0 --R0, π0--> z1 --R1, π1--> z2 --R2, π2--> ... --Rn, πn--> zn

public inputs: taskId, contractRoot, z0, zn, ruleHash, stepCount
final check:   Verify(vk, publicInputs, foldedProof) = true
```

增量证明只覆盖能被精确定义为电路关系的步骤。人工审批、开放式写作和不确定工具调用仍需转成签名回执或其他可验证输入。

### PoI 的定义与限制

此处的 Proof of Intelligence 是一种贡献凭证，不是通用智能评分。有效凭证要求需求方签名任务，输出绑定冻结输入和执行上下文，Validator 按预先声明的条件验收，并且 nonce 尚未使用。

```ts file="poi-eligibility.ts"
function eligibleForContribution(task: Task, proof: ExecutionProof, verdict: Verdict) {
  return verifyIntentSignature(task.intent)
    && proof.taskId === task.id
    && proof.inputRoot === task.inputRoot
    && verdict.outputRoot === proof.outputRoot
    && verdict.accepted
    && independent(task.requester, proof.worker, verdict.validators)
    && !replayRegistry.has(task.nonce)
}
```

主要机制风险包括自交易、低价值刷单、Validator 串谋和任务难度不可比。生产协议必须定义独立性、价值权重、声誉衰减和审计抽样。
