### 仓库当前提供什么

当前 ACVM 仓库提供**交互式协议教程与概念规格**，用状态图、公式和 TypeScript 示例描述 Agentic Contract VM 的设计边界。仓库尚未包含可部署任务的完整虚拟机实现。文中出现的接口是说明性设计；协议不变量和待选技术会明确标注。

ACVM 的第一项设计决定是把业务契约从“一个链上函数”扩展为内容寻址目录。Schema 冻结输入输出结构，Worker 描述执行，Validator 描述验收，Settlement 描述满足什么条件才可结算；规范排序和哈希后得到 `contractRoot`。

```text file="agentic-contract.tree"
contract/
├── contract.ts          # manifest, roles, limits
├── schema/
│   ├── input.json
│   └── output.json
├── worker/index.ts      # off-chain work
├── validator/index.ts   # independent acceptance
└── settle.ts            # deterministic settlement rule

contractRoot = MerkleRoot(canonicalPath || hash(fileBytes))
```

这只证明“运行的是哪一版目录”。目录内的规则是否合理、依赖是否安全、Validator 是否足够独立，仍要靠审核、治理与争议机制处理。

### 最小合约清单

以下代码是用于说明职责分离的**示例接口**，仓库尚未发布同名 SDK。业务目录声明入口和约束；运行时注入文件、预言机、链适配器与回执能力。

```ts file="contract.ts"
import { defineContract } from '@a3s-lab/acvm'

export default defineContract({
  schema: {
    input: './schema/input.json',
    output: './schema/output.json',
  },
  stages: {
    worker: './worker/index.ts',
    validator: './validator/index.ts',
    settlement: './settle.ts',
  },
  limits: {
    budget: 50_000n,
    deadlineBlocks: 240,
  },
})
```

```ts file="worker/index.ts"
export async function run(ctx: AgenticContractContext) {
  const order = await ctx.files.readJson('/task/input/order.json')
  const quote = await ctx.oracle.fetchJson(order.quoteUrl)
  const result = await produceRecommendation(order, quote.value)

  await ctx.files.writeJson('/task/worker/result.json', result)
  await ctx.files.writeJson('/task/worker/source-proof.json', quote.proof)
  return ctx.receipt.commit('worker')
}
```

Validator 不复用 Worker 的进程内对象，而是从固定路径读取输入、结果和证据。这样任务树根可以覆盖角色之间的真实交接物，重试和争议也能回到同一份版本化上下文。

### 七个阶段与三类记录

部署阶段确定 `contractRoot`；调用阶段把签名 Intent、输入根、预算和期限绑定为 `taskId`；执行与验收阶段分别产出 Worker 和 Validator 回执；共识阶段只验证确定性证据；结算阶段转移资产并封闭 nonce。

这条流程里有三类事实不能混淆：

1. **授权事实**：谁允许做什么，预算和期限是什么。
2. **执行事实**：哪版代码处理了哪份输入，产出了哪份结果。
3. **验收事实**：谁按哪版规则判断结果合格，以及裁决是否已终局。
