### 解析记录的验证

Agent Name Service 可以把人类可读名称映射到 DID、A2A 端点、能力声明、计价、有效期和推荐 Validator 集。调用方仍要验证记录签名、凭证撤销、端点绑定和新鲜度，再根据任务类型选择合适服务。

```ts file="agent-record.ts"
type AgentRecord = {
  name: string
  did: string
  a2aEndpoint: `https://${string}`
  capabilityRoot: `0x${string}`
  pricingRoot: `0x${string}`
  validatorSet: string[]
  validUntil: bigint
  sequence: bigint
  signature: `0x${string}`
}
```

信誉不能只用一个全局分数。它至少应按任务类型、难度、时间窗口和争议结果分域，并让调用方看到样本量与置信范围，避免过期成绩和选择性展示。

### 组合协议的三个不变量

父任务可以拆成 DAG，但必须保持：子任务预算总和不超过父任务可用预算；子能力只能是父能力的子集；父任务进入验收前，所有必需子任务都必须有终局回执。可选分支和失败回退也要在部署规则中冻结。

```ts file="aggregate-child-receipts.ts"
function aggregate(parent: ParentTask, children: ChildReceipt[]) {
  const required = parent.graph.nodes.filter((node) => node.required)
  assert(required.every((node) => children.some((r) => r.taskId === node.taskId)))
  assert(children.every((receipt) => receipt.status === 'finalized'))
  assert(sum(children.map((receipt) => receipt.cost)) <= parent.remainingBudget)
  assert(children.every((receipt) => parent.capability.contains(receipt.capability)))

  return merkleRoot(children.map(canonicalReceipt))
}
```

聚合根压缩了证据，但父 Validator 仍要按需检查关键子回执与包含证明，不能把“根存在”误当成“所有子结果正确”。

### 链适配器的安全边界

不同链拥有不同账户模型、Gas、事件、最终性和证明验证能力。适配器可以统一 `submitIntent`、`commitReceipt`、`challenge` 和 `settle` 等操作，但每个实现必须声明底层最终性条件和可用证明类型。

```ts file="chain-adapter.ts"
interface ChainAdapter {
  submitIntent(intent: SignedIntent): Promise<TransactionRef>
  commitReceipt(receipt: Receipt): Promise<TransactionRef>
  waitForFinality(ref: TransactionRef): Promise<FinalizedBlockRef>
  verifyRemoteState(proof: StateProof): Promise<boolean>
  settle(taskId: string): Promise<TransactionRef>
}
```

跨链场景不能用一个适配器接口掩盖安全差异。远端回执要通过轻客户端或明确的桥接信任模型验证；任务超时必须按目标链重组窗口与最终性规则配置。

### 一个结果要触发付款，至少回答五个问题

1. **谁授权**：身份、能力和预算由谁签名，权限能否在委托中收窄？
2. **做了什么**：输入、代码、模型、工具和输出怎样绑定到同一个 `taskId`？
3. **凭什么接受**：计算、来源和结果质量分别由哪类证据或 Validator 判断？
4. **失败怎样收场**：超时、挑战、申诉、补偿和跨链部分成功怎样进入确定性状态？
5. **何时可以结算**：底层链达到什么终局条件后，资产与责任才能不可逆地转移？

```text file="acvm-thesis.txt"
usageCost = meter(requests, tokens, compute)

payout = escrow × 1[
  accepted(intent, evidence, verdict)
  && challengeClosed
  && finalityReached
]

Usage measures cost. Verified outcomes trigger settlement.
```

如果一项设计只能展示 Agent 输出，却说不清付费结果、证据、验收、失败和终局，它仍是带钱包的链下服务，不是结果付费基础设施。
